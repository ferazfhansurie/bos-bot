# 2.1.3 lane contracts

## remote config (lane 3 → lane 1)

`GET https://bosbot.my/api/app-config` returns JSON with optional
`minVersion: {desktop?: string, ios?: string, android?: string}`. Values are
stable `major.minor.patch` versions. `flags.autoUpdates: true` enables ordinary
quiet downloads/install-on-quit; false/missing/offline keeps updates manual.
A successfully fetched minimum overrides that rollout flag for compatibility. Missing, invalid or unreachable config
never blocks desktop launch. Desktop checks on launch with an 8 second timeout.
A required minimum, and any manual "Check for updates", bypasses the native
rollout percentage; quiet background checks keep native staged eligibility. Desktop update actions wait for the bounded
config fetch before native staging; candidates below the floor never stage. Never set the floor above a published feed version. The required screen blocks only while a qualifying update is available, downloading, preparing, downloaded or installing; idle, error, held and hand-off states are a dismissible card.
Lane 3 owns the endpoint/cache; desktop reads this same public contract directly
because its native updater must work before the renderer/server config loads.

## update state (lane 1 → lane 3)

Electron atomically writes `<dataDir>/update-state.json`, no credentials/messages:
`{update_state: "idle" | "checking" | "downloading" | "downloaded" | "failed:<class>", updatedAt: string}`.
Classes are `network`, `feed`, `verification`, `install`, `unknown`.
`server/update-state.ts` exports `readUpdateState(dataDir: string): UpdateState`
for the ping/events and health lanes. Missing/invalid files return `idle`.
Do not import Electron into the server. Preparing maps to downloading;
installing/handed-off map to downloaded. Errors never include raw text in telemetry.

## phone compatibility

The server environment descriptor adds `minPhoneVersion: string` and
`phoneUpdateUrls: {ios: string, android: string}`. Defaults are `2.1.3`,
`https://bosbot.my/get`,
and `https://bosbot.my/updates/android.json`; no store/testflight URL currently exists in source (descriptor overrides accept
HTTPS distribution links). Older descriptors lacking the fields remain
compatible. Native clients check the descriptor before fetching normal models.

Mac native staging arms installation on termination. Every subsequent quit,
including preparing/error states and repeat requests, requires the existing
server lifecycle prepare/commit receipt. No owned/ready server counts as idle
and the quit is admitted. A busy refusal clears the nonce, shows a held quit
with "Quit without waiting", and retries every 5s for up to 2 minutes; a quit
repeated after a refusal tries once more, then quits without waiting. A nonce
from a prepared receipt survives a server restart (same host generation). Windows vendor quit hooks stay
disabled; the coordinator installs on quit after the same admission.

# 2.1.3 self-heal contracts

- `server/safe-mode.ts`: `isSafeMode()`, `safeModeStatus()` → `{enabled,reason}`,
  `allowInSafeMode("mods" | "plugins" | "routines")`. The desktop passes
  `BOS_SAFE_MODE=1` and `BOS_SAFE_MODE_REASON` for one final supervised boot.
  Lane 4 must gate mod loading and every bridge execution with this function.
  Exiting safe mode relaunches the desktop; it never enables systems in place.
- `electron/self-heal-policy.mjs`: `selfHealEnabled(dataDir)` reads lane 3's
  cached `app-config.json`, requiring `{version:1,flags:{selfHeal:true}}`.
  Missing/invalid cache defaults off. This gates automatic safe-mode fallback,
  one-tap repairs and report upload; data protection, recovery notices, the
  read-only doctor and exiting safe mode always remain available.
- `GET /api/doctor`: `{checkedAt,checks,notices,safeMode,selfHealEnabled}`; each check is
  `{id,status,detail,fix?}`. `POST /api/doctor/fix {action:"reconnect-whatsapp"}`
  is an explicit owner action. The bot `health_check` tool uses the same checks.
- `server/recovery-notices.ts`: `recoveryNotices(dataDir)` returns bounded
  collection notices for `bots.json`, `groups.json`, `messages.db`; statuses
  `restored`, `read-only`, `fresh`. Health displays the one-line detail.
- A roster read fails (and quarantines) only when the store cannot load it:
  not a JSON array of objects, a record without a non-empty string `id` or
  `threadId`, or a `groups.json` record without an array `memberIds`. Ids keep
  whatever shape older builds wrote. A symlinked or non-file canonical is
  refused; a hard link is allowed. The first good read seeds `<name>.bak` when
  none exists, so a pre-2.1.3 install has a backup before its first save.
- Roster `.bak` files contain the last successful save. A failed read creates
  `<name>.read-only` before quarantine, so another boot cannot treat it as new.
  Workspace restore safety copies in `.backups/safety-<id>/data` are secondary
  recovery sources. Encrypted exports still require their password and are
  never silently decrypted or retained as new plaintext snapshots.
- Message recovery runs `quick_check` before migrations, quarantines the main
  file and old sidecars, and restores the newest valid supported local backup.
  A missing valid backup creates a new DB with a visible notice. Lock/permission
  errors do not trigger a reset. `.recovery-pending` resumes interrupted moves.
- Safe mode, claude driver: `--strict-mcp-config`, `--setting-sources ""`
  (each only when the CLI version supports it) and `--disable-slash-commands`;
  never `--safe-mode` (it drops the harness MCP tools, including
  `health_check`, and older CLIs reject it). Codex: plugins, remote plugins,
  hooks and user `mcp_servers` off. Routines don't tick; run-now and webhook
  enqueue throw.
- `window.ogb.health.sendDiagnostics()` → `Promise<{id:string}>` sends only on
  the explicit button action. `exitSafeMode()` → `Promise<void>` relaunches.
  Diagnostics receiver: `POST https://bosbot.my/api/diag`, JSON
  `{report:string}` (existing redacted text bundle), maximum total body 5 MiB,
  response `{id:string}`. Lane 3 must accept the text report shape.
- Desktop `<dataDir>/crash-count.json`: `{count:number,lastCrashAt:string}`,
  monotonic best-effort count of unexpected owned server / desktop crashes.
  Lane 3 ping may read it; absence/unreadable means unavailable, never zero.
- Doctor consumes lane 1 `<dataDir>/update-state.json`:
  `{update_state,updatedAt}`; no file means unavailable.
- Integration follow-up for lead: bind actual successful heal outcomes to
  lane 3 `recordProductEvent("heal_ran",{check:"storage"|"whatsapp"})`.
  Data-loss prevention is unconditional; optional actions honor `flags.selfHeal`.
- Phone overlap with lane 1: preserve `serverWasReset = true` in its rewritten
  environment-id mismatch guard. iOS `registerPushToken` returns a response
  with optional `deliveryConfigured`; explicit false means unavailable.

# 2.1.3 lane 3 contracts

- `shared/app-config.ts`: `AppConfig`, `DEFAULT_APP_CONFIG`, `parseAppConfig(unknown)`.
  Public config: `{version:1,minVersion:{desktop,ios,android},flags,banner,pricing,starterJobs,rollout}`.
  Minimum versions default to `0.0.0`; unavailable config never forces an update.
  `flags`: `activationTelemetry`, `freeEngine`, `plans`, `invite`, `feedback`,
  `starterJobs` default true; `autoUpdates`, `selfHeal`, `mods` default false.
  `rollout`: desktop/ios/android percentages (0–100). Banner is null or `{id,text,url}`.
  Pricing: `{id,title,priceMYR,unit,status:'available'|'coming_soon',url,description}`.
  Starter job: `{id,title,prompt}`. Only HTTPS links are accepted.
- `server/app-config.ts`: `AppConfigClient({dataDir,fetch?})`, `.current()` (cached
  snapshot or built-in defaults), `.refresh()` (bounded, silent offline failure).
  Cache is `<dataDir>/app-config.json`; URL `https://bosbot.my/api/app-config`.
- Local `GET /api/app-config` returns the config directly. `GET /api/product`
  returns `{config,analyticsEnabled,referralUrl}`. Renderer hook:
  `src/lib/app-config.ts` exports `useAppConfig()` and `getAppConfig()`.
- `server/product-telemetry.ts`: `ProductTelemetry.track(name,props?)`; the host
  exports `recordProductEvent(name,props?)` from `server/product-events.ts` so
  update/heal/mod code need not import `server/index.ts` or create another sender.
  `update_installed`, `heal_ran` (`check`), `mod_created`, `error` (`class`) are
  emitted only from actual outcomes. Enums for check/class: `engine`, `network`,
  `auth`, `storage`, `update`, `push`, `whatsapp`, `server`, `unknown`.
  Module drops opaque properties. Full event/prop allowlist: `shared/product-events.ts`.
  Lane 4's actual successful UI writes/enables may also use renderer
  `track("mod_created")` / `track("mod_enabled")`; local ingress accepts both.
  Same `anonymous-usage.json` id, anonymousUsage opt-out and `BOS_NO_PING=1` as ping.
  Daily ping reads optional `<dataDir>/update-state.json` / `crash-count.json`
  through `productHealth()`: sanitized `update_state` and `crash_count` only;
  invalid/missing state is omitted. Lanes 1/2 own those writers.
- Local `POST /api/product/events {events:[{name,props}]}` forwards safe renderer
  counts to the server batch. At most 50 per request/batch, queue capped at 500,
  flush every 60s and on shutdown. Public endpoint `https://bosbot.my/api/events`:
  `{install_id,version,platform,events:[{name,at:ISO8601,props}]}` (64KB).
- Local `POST /api/product/claim {email}` is called only for a typed email after
  onboarding; remote `/api/claim` adds the canonical install_id and joins only a
  latest consented signup of that email. No email enters event properties.
- Local `POST /api/product/feedback {text,rating?:'up'|'down'}` requires explicit
  UI consent and proxies to remote `/api/feedback` with the canonical install_id.
  Empty text plus rating is allowed. Never send a transcript or message id.
- Local `POST /api/product/job-done {confirmed:true}` records `first_job_done`
  only after user confirmation and a successful local conversation result.
- Lane 2 diagnostics: remote `POST https://bosbot.my/api/diag`, JSON or JSON/text
  multipart, 5MB max; `{install_id?,report:string|object}`, response `{id}`. Redact client
  side; receiver also strips common secrets/paths. Binary archives are refused.
  Lane 2's exact `{report:string}` shape is supported without inventing an install id.
- Phones use their own durable random device id; `install`, `open`,
  `pair_success`, `push_ok` go to the public events endpoint. Push requires a
  positive server deliveryConfigured receipt. No Android push claim without FCM.
- Referral: first 16 hex of SHA-256(`bos-referral-v1:` + canonical install_id);
  link `https://bosbot.my/get?ref=<code>`. It is attribution, never identity or access.

# 2.1.3 mods contract (lane 4)

- Mods live under the configured `DATA_DIR/mods/<id>`, never a hardcoded home.
- `GET /api/mods`, `GET|PUT|DELETE /api/mods/:id`, `POST /api/mods/:id/enabled` (`{enabled,revision}`; enabling requires the revision just reviewed), `GET /api/mods/:id/export`, `POST /api/mods/import` (JSON `.bosmod` bundle). Writes/imports start disabled; enabling is an owner action after permission review.
- Bot tools use `/api/internal/mods` with the existing turn capability. They may list/get/write/delete their own mods, never enable them or touch another bot's mod.
- `POST /api/mods/:id/bridge` requires `{botId,revision,request}`, binds to the active bot, checks the current manifest and enable state, validates each operation, limits requests and times them out. No new mobile events or fields.
- Safe-mode adapter `modsSuspended(DATA_DIR)` consumes lane 2's canonical `BOS_SAFE_MODE=1` contract. Lane 3's cached `<dataDir>/app-config.json` `flags.mods` must be explicitly true (absent, malformed or false means off). No network fetch or duplicate config client.
- Lane 3's current `shared/product-events.ts` allowlist includes both `mod_created` and `mod_enabled`.
- Analytics calls: `track("mod_created")`, `track("mod_enabled")`; no content props.
